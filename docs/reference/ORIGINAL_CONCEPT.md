聪宝，我建议把《午夜清扫队》定成一款 **2D俯视角、单人、每局约15—20分钟的动作生存游戏**。玩家驾驶一台改装清扫机器人，在夜间回收场里消灭失控机械，收集零件、购买工具，最后击败巨型垃圾压缩车。

**它最值得打磨的特色是：把敌人打散，把零件吸回来，再把积攒的能量喷出去。** 这套动作既能制造爽感，也能让“清扫队”这个题材真正影响玩法。

下面是我会采用的具体设计。数量、时长和数值都是开发目标，最终要靠试玩调整。

1. **先确定玩家在这款游戏里获得什么乐趣。**

   我希望它有三种明确的快乐：

   **第一种是操作上的解压。** 一群机械虫被滚刷打碎，螺丝和电池散落一地；玩家启动吸附，零件沿弧线飞进机器，能量条迅速充满；松开按键，一次喷射把面前的敌人全部冲开。

   **第二种是搭配成功的满足。** 单独一把泡沫喷枪只能减速敌人，加上电弧武器之后，泡沫覆盖的敌人会成为更好的导电目标，一片敌人连锁放电。玩家能看懂“为什么我的装备突然变强了”。

   **第三种是从危险中脱身的成就感。** 被包围时，通过吸附聚拢一侧敌人、喷射打开缺口、冲刺离开，靠一次正确操作救回局面。

   自动攻击、短波次战斗和波间商店，可以参考《Brotato》已经采用的结构；我们的设计重点放在清扫工具和吸附喷射之间的配合。[《Brotato》官方介绍](https://store.steampowered.com/app/1942280/Brotato/)

2. **世界观可以很简单，但角色和场景要有自己的味道。**

   故事发生在一座高度自动化城市。某天午夜，回收系统发生故障，废弃家电、运输设备和机械零件开始自行拼装，整个回收场变成了危险区域。

   玩家扮演夜班清扫机器人，接到的任务是：在早班人员到来之前，恢复回收场运行。

   我会做两个可选角色：

   | 角色     | 外形与性格             | 玩法特点                    |
   | ------ | ----------------- | ----------------------- |
   | **小圆** | 圆形机身、黄色警示灯，有点认真过头 | 移动灵活，回收能量积攒较快，适合频繁吸附和喷射 |
   | **铲铲** | 小型履带车，前面装着铲斗      | 行动较慢，耐久和击退能力更强，适合近身清场   |

   角色个性主要通过动画表现：小圆吸入过多零件时机身轻微鼓起，铲铲受到冲撞时铲斗会晃动。开场、首领出场和通关各安排一段短演出，就能形成完整故事。

3. **操作保持简单，核心主动能力从开局就有。**

   我会用下面这套键鼠操作：

   | 操作   | 功能              |
   | ---- | --------------- |
   | WASD | 移动              |
   | 自动攻击 | 装备根据自身规则寻找目标并攻击 |
   | 鼠标方向 | 控制吸附与喷射的朝向      |
   | 按住右键 | 吸附前方零件，并牵引轻型敌人  |
   | 松开右键 | 消耗当前回收能量，向前喷射   |
   | 空格   | 短距离冲刺，有冷却时间     |
   | Esc  | 暂停与设置           |

   **吸附和喷射共用一个按键，是我很想保留的设计。**

   按住时，玩家会略微减速，前方零件迅速聚拢，轻型敌人也会被拉近。松开后，根据积攒的能量形成一次冲击：能量少时用于推开敌人，能量多时产生明显伤害和更宽的清场范围。

   为了让操作公平，吸附不会直接把敌人拉进玩家的受伤判定区域；重型敌人受牵引较弱，首领主要受到伤害和特定阶段的硬直影响。

   这里还要明确区分两个东西：

   * **零件货币：**用于商店购买装备。
   * **回收能量：**用于喷射，属于战斗资源。

   吸入一份零件，可以同时增加货币和能量；喷射只消耗能量。玩家可以放心使用自己的招牌技能。

4. **一局应该有明显的起伏，最终有一次真正的通关。**

   我建议一局安排 **12波战斗**，普通波约45—60秒，首领波以击败首领为结束条件。

   | 阶段     | 玩家体验               | 设计重点            |
   | ------ | ------------------ | --------------- |
   | 第1—3波  | 学会移动、回收和喷射，拿到第二件武器 | 很快形成基本战斗能力      |
   | 第4—5波  | 敌人开始组合出现，装备搭配显出效果  | 第一次感到自己的选择有价值   |
   | 第6波    | 中途首领               | 检查玩家是否理解闪避和技能使用 |
   | 第7—11波 | 装备逐步成型，敌人组合更复杂     | 强度提升，同时保留反击空间   |
   | 第12波   | 最终首领               | 运用整局形成的打法完成决战   |

   每波结束进入安全的维修区，玩家可以慢慢看商店。战斗本身目标约12分钟，连同购买和选择，典型一局控制在15—20分钟左右。

   普通波结束时，剩余敌人撤离，未拾取零件自动结算为货币。主动回收的价值在于：**战斗过程中就能获得喷射能量，马上用来解围或进攻。**

   生命归零后进入结算，展示本局装备、最高波次和主要伤害来源，并提供快速重开。击败最终首领后，回收场恢复运转，天色转亮，进入完整通关画面。

5. **六种武器已经能支撑不少打法，关键是功能差异。**

   玩家拥有4个武器槽，开局带一件基础工具。每种武器设3个等级，升级集中改善它的主要特点。

   | 武器        | 基础效果              | 玩家怎样围绕它行动            |
   | --------- | ----------------- | -------------------- |
   | **旋转滚刷**  | 持续伤害身边的敌人         | 保持合适距离，用吸附把轻敌人拉到滚刷边缘 |
   | **铆钉枪**   | 发射直线弹体，升级后获得穿透能力  | 调整站位，让敌人排成一条线        |
   | **泡沫喷头**  | 给敌人附着泡沫，降低移动速度    | 控制追兵，给其他武器创造输出时间     |
   | **电弧除尘器** | 电流在附近敌人之间跳跃       | 把敌人聚到一起，优先利用泡沫目标     |
   | **回旋锯盘**  | 锯盘飞出后返回，可在往返时命中敌人 | 移动角色，让回程锯盘扫过更多目标     |
   | **清扫无人机** | 在角色附近巡航，自动攻击目标    | 提供稳定火力，让玩家更专注于走位和回收  |

   其中，我最希望做出三套清晰的搭配：

   **聚怪滚刷流。** 滚刷负责近身输出，泡沫降低敌人速度，吸附把零散敌人集中起来，喷射负责在危险时打开距离。它的风险和收益都很直观。

   **泡沫电弧流。** 先控制一群敌人，再通过电弧造成连续伤害。清理密集杂兵很强，面对分散的远程敌人则需要主动追击。

   **锯盘游走流。** 回旋锯盘配合移动和冲刺，让敌人反复经过锯盘路径。对操作更有要求，但可以打出漂亮的连续穿击。

   我会让一部分改装直接改变行为，例如“喷射变成两段”“锯盘返回时扩大”“回收时获得短暂护盾”。其余改装提供伤害、射速、耐久等基础提升，帮助玩家补足短板。

6. **敌人要改变玩家的行动，不能全都只会追着跑。**

   完整版本可以控制在8类普通敌人：

   | 敌人        | 行为          | 给玩家提出的问题       |
   | --------- | ----------- | -------------- |
   | **螺丝虫**   | 数量多、缓慢追踪    | 能否高效清理并收集资源？   |
   | **弹簧鼠**   | 停顿蓄力后直线冲刺   | 能否看懂预警并及时侧移？   |
   | **盾壳车**   | 正面防护较强      | 能否绕侧面或利用穿透攻击？  |
   | **喷污罐**   | 远程发射缓慢污染弹   | 能否离开原来的绕圈路线？   |
   | **磁铁怪**   | 把附近掉落零件吸向自己 | 是否值得优先追击它？     |
   | **电池雷**   | 靠近后闪烁，随后爆炸  | 能否及时击退或拉开距离？   |
   | **维修机**   | 修复周围敌人      | 能否找到并处理支援单位？   |
   | **重型清运机** | 缓慢推进，难以被吸附  | 能否在它和小怪之间保持空间？ |

   难度主要通过组合提升。例如，盾壳车逼你绕行，喷污罐则让绕行路线变得危险。

   **两个首领也应该围绕已有规则设计。**

   中途首领可以是“失控叉车”：先亮出冲撞路线，再冲刺撞向场地边缘；撞击后短暂暴露弱点。它让玩家学会观察预警、闪避和抓住输出窗口。

   最终首领是“巨型压缩车”：用吸风口牵引玩家、投放废料、进行横向扫击。阶段切换时打开散热口，玩家可以把积攒的喷射打进弱点，制造一次明显硬直。

   首领的弱点机制提供奖励，普通武器也始终能造成有效伤害，保证不同装备组合都有通关办法。

7. **画面和声音，要让人一眼看懂，又有清扫的满足感。**

   我倾向于**轮廓清晰的卡通工业风**：深蓝灰色地面，暖黄色玩家机身，青绿色回收零件，红橙色危险提示。

   场景里可以有传送带、废旧家电、围栏和警示灯，但战斗区域要留出足够空地。角色、敌人、掉落物和危险区域还要用形状区分，方便玩家在特效密集时判断。

   最值得投入时间的表现是：

   * 零件被吸入时，有明显的加速轨迹和逐渐升高的机械声。
   * 喷射前有短促蓄力，释放时有气浪、击退和低频声音。
   * 敌人被击中时有轻微形变、闪光和方向明确的受力反馈。
   * 大批敌人被清理后，地面能短暂显得干净，给玩家一个视觉上的结果。

   屏幕震动和闪光强度应可调。界面保留血量、波次、货币、回收能量、冲刺冷却和4个武器槽，尽量把注意力留给战场。

8. **我会把完整1.0版本的范围定得很明确。**

   | 内容   | 建议范围                       |
   | ---- | -------------------------- |
   | 角色   | 2个，具有不同操作倾向                |
   | 场景   | 1个回收场主题、2套障碍布局             |
   | 武器   | 6种，每种3级                    |
   | 改装   | 约20项，其中一部分改变技能行为           |
   | 敌人   | 8类普通敌人、2个首领                |
   | 单局流程 | 12波，包含商店、失败和通关结算           |
   | 重复游玩 | 随机商店、角色解锁、3档难度、少量挑战成就      |
   | 基础功能 | 首局引导、暂停、音量设置、按键设置、波间存档     |
   | 交付   | Windows发行包、浏览器试玩版、完整源代码与说明 |

   局外成长以解锁新角色、装备和难度为主。基础角色从一开始就具备通关能力，玩家通过理解规则和调整装备逐渐进步。

   波间存档尤其适合这个项目：进入商店后保存当前装备、货币、波次和随机状态，下次可以从这个安全节点继续，开发成本也比较容易控制。

9. **技术上，我推荐 Godot 4.x＋GDScript。**

   在你没有既定引擎偏好的情况下，我会选择开工时的一个稳定版本并固定下来，使用带类型标注的GDScript，采用2D场景和Compatibility渲染方式。

   这条路线适合同时准备桌面版本和浏览器试玩。当前Godot官方文档说明，Godot 4的Web导出使用Compatibility渲染，C#项目目前不能直接导出Web，因此这里选择GDScript更合适。[Godot Web导出文档](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_web.html)

   项目可以按以下职责组织：

   | 模块          | 负责什么               |
   | ----------- | ------------------ |
   | `player/`   | 移动、冲刺、吸附、喷射和玩家动画   |
   | `enemies/`  | 各类敌人的行为、预警和首领阶段    |
   | `combat/`   | 伤害、击退、状态效果、弹体和目标选择 |
   | `weapons/`  | 武器运行逻辑、开火方式和升级效果   |
   | `run/`      | 波次、刷怪、商店、货币和本局状态   |
   | `content/`  | 武器、敌人、改装、波次的配置数据   |
   | `ui/`       | 战斗界面、菜单、商店和结算      |
   | `services/` | 存档、声音和随机数管理        |

   **最重要的架构决定，是把配置数据和运行状态分开。**

   例如，铆钉枪的基础伤害、图标和弹体类型放在配置里；这局玩家的武器等级、当前冷却和临时增益放在武器实例里。Godot的Resource适合保存这类配置，但加载的资源可能被多个对象共享，因此不能随手把某个玩家的临时状态写回共享配置。[Godot Resource文档](https://docs.godotengine.org/en/stable/tutorials/scripting/resources.html)

   伤害也应统一结算。防御、增伤、暴击和状态效果的先后顺序只定义一次，所有武器共同使用，后续平衡和排错会轻松很多。

10. **开发顺序应该围绕“每一步能玩到什么”安排。**

    | 阶段        | 做出什么                  | 进入下一阶段的判断依据          |
    | --------- | --------------------- | -------------------- |
    | **核心操作**  | 角色、两类敌人、一把武器、零件、吸附和喷射 | 连续玩几分钟，能感到吸附与喷射有用、顺手 |
    | **一局打通**  | 波次、商店、死亡、结算和一个首领      | 可以从开始完整玩到失败或胜利，再正常重开 |
    | **扩充内容**  | 全部武器、敌人、改装与第二角色       | 至少三套搭配能够形成不同的行动方式    |
    | **表现与平衡** | 动画、音效、引导、难度与性能调整      | 新玩家能理解规则，失败后知道主要原因   |
    | **发行交付**  | 存档、导出、说明文档、演示视频       | 别人拿到发行包或打开试玩链接就能开始玩  |

    如果由一个熟悉引擎的人开发、配合AI辅助、采用范围明确的美术素材，我会先按**约6—10个全职周**预留工作量。这是初步估算；如果同时学习引擎或自己制作全部美术，需要增加时间。

    使用AI协助时，每个任务都应有明确边界。例如：“实现吸附范围、零件收集和释放喷射，并验证一次零件只记账一次。”完成并运行检查之后，再继续下一个模块。

    每一个阶段都留下可运行的Git版本，后面调整手感或平衡时，才容易比较和回退。

11. **真正需要提前照顾的风险，是性能、组合平衡和操作反馈。**

    性能方面，这种游戏容易同时出现大量敌人、弹体和掉落物。我会很早准备一个压力场景，在明确记录配置的测试电脑上，以1080p、60帧为目标观察表现。

    武器寻找目标、敌人相互避让、反复创建弹体，都可能成为瓶颈。先用分析工具找出最耗时的部分，再决定是否降低查询频率、合并掉落物或复用弹体实例。Godot官方也建议通过实际测量指导优化，并在修改后重新验证。[Godot性能优化文档](https://docs.godotengine.org/en/stable/tutorials/performance/general_optimization.html)

    平衡方面，优先看三个问题：近战是否总在吃亏；清群能力强的组合是否完全打不动首领；玩家是否经常连续几波买不到有意义的装备。

    测试则集中在容易破坏整局体验的地方：伤害与增益叠加、重复死亡掉落、购买与扣款、存档恢复、暂停以及重新开始后的状态清理。

    **手感需要真人试玩。** 让几位没有参与开发的人玩第一局，观察他们在哪里困惑、什么时候主动使用喷射、死亡后是否愿意马上重开。相比不断增加新装备，这些反馈更能决定游戏是否值得玩下去。

12. **GitHub上的展示，要围绕这款游戏已经实现的体验。**

    仓库首页可以按这个顺序呈现：一段20—30秒的战斗演示、试玩或下载入口、操作说明、特色机制、运行步骤，再介绍核心代码结构。

    技术说明重点写清楚三个值得看的部分：吸附与喷射怎么实现、装备效果怎样组合、密集战斗怎样保持性能。标明引擎版本和素材来源，保留能够复现的构建步骤。

    **我建议真正开工时的第一个任务，就是做出三分钟的“打碎敌人—吸回零件—喷射清场”。** 这段体验顺手、有力量感，整个项目就有了可靠的基础，后面的武器、敌人和成长系统都能围绕它展开。

如果有用，可以设个“每周提醒我试玩并复盘游戏”，定期检查手感和平衡问题。
